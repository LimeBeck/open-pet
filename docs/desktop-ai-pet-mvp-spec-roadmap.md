# Desktop AI Pet — спецификация и roadmap MVP

Статус: Draft v0.3  
Дата: 7 августа 2026  
Первичная платформа: KDE Plasma 6.2+ / Wayland  
Стратегия продукта: общее ядро и UI, сменные платформенные адаптеры

## 1. Резюме

Desktop AI Pet — постоянно доступный анимированный питомец поверх рабочего стола рядом с панелью KDE Plasma. Он реагирует на обезличенные признаки активности пользователя и системные события, меняет эмоцию и анимацию, показывает короткие реплики и опционально использует подключённую LLM.

MVP должен доказать четыре гипотезы:

1. Питомец органично живёт на рабочем столе и не ощущается обычным окном.
2. Реакции на локальные события выглядят уместно и не раздражают.
3. Privacy-first режим полезен без чтения текста, клавиш, экрана или аудио.
4. Архитектура позволяет добавить Windows, macOS и другие Wayland-композиторы без переписывания ядра.

## 2. Зафиксированные продуктовые решения

| Область | Решение MVP |
|---|---|
| Эталонная среда | KDE Plasma 6.2+ на Wayland |
| UI | Qt 6 + QML |
| Overlay | LayerShellQt |
| Общее ядро | Rust |
| Взаимодействие мышью | Питомец всегда интерактивен в своей видимой области |
| Наблюдение ввода | Только факт активности/простоя; без клавиш и текста |
| Системные сигналы | Батарея/питание, сон/блокировка, активное приложение, уведомления, медиавоспроизведение |
| Реакции | Анимация/эмоция и короткая реплика |
| Реплики | Локальные шаблоны по умолчанию; LLM включается явно |
| LLM | Ollama, OpenAI-compatible, Google Vertex AI через единый интерфейс |
| Визуалы | Импорт безопасного Pet Pack; генератор визуалов — отдельный будущий skill |
| Сеть | Не требуется для базовой работы |

## 3. Пользовательская ценность MVP

Пользователь устанавливает приложение, выбирает питомца и сразу видит его рядом с панелью. Питомец просыпается при возвращении пользователя, засыпает после простоя, реагирует на зарядку и низкий заряд, замечает смену рабочего контекста и ненавязчиво отзывается на уведомления или воспроизведение медиа. Все реакции работают локально. При желании пользователь включает LLM, чтобы разнообразить формулировки, не передавая модели сырые системные события.

## 4. Границы MVP

### 4.1 Входит в MVP

- Прозрачный overlay без рамки и записи в панели задач.
- Размещение у выбранного края/угла экрана; сохранение позиции.
- Поддержка одного питомца и одного активного Pet Pack.
- Интеракции: одиночный клик, перетаскивание, контекстное меню.
- Tray-меню: показать/скрыть, настройки, пауза реакций, выход.
- Состояния: `idle`, `happy`, `curious`, `sleepy`, `charging`, `low_battery`, `notification`, `busy`.
- Локальный rule engine с приоритетами, cooldown и защитой от спама.
- Локализованные шаблонные реплики, минимум `ru` и fallback `en`.
- Импорт и валидация Pet Pack v1.
- Адаптеры системных событий для KDE Wayland.
- Настройки приватности и отдельные переключатели источников событий.
- Опциональные LLM-провайдеры с тестом подключения, тайм-аутом и fallback на шаблоны.
- Локальный диагностический журнал без пользовательского содержимого.
- Автозапуск по явному выбору пользователя.

### 4.2 Точное значение неоднозначных событий

| Событие | Что видит MVP | Что MVP не получает |
|---|---|---|
| Клавиатура/мышь | Время последней активности и переход idle/active | Клавиши, координаты, текст, частоту кликов |
| Активное приложение | Нормализованный app id и факт смены | Содержимое окна, заголовок документа по умолчанию |
| Уведомление | Факт события и необязательная категория | Текст, отправитель, вложения |
| Звук | `playing/paused/stopped` для MPRIS-совместимого медиаплеера | Аудиопоток, микрофон, распознавание звука |
| Экран | Ничего | Скриншоты, OCR, видеопоток |

Если безопасный источник события недоступен, соответствующая capability помечается `unsupported`, а приложение продолжает работать без неё.

### 4.3 Не входит в MVP

- Чат, голосовое управление и выполнение команд пользователя.
- Чтение текста уведомлений, ввода, буфера обмена или содержимого экрана.
- Управление окнами и приложениями.
- Несколько питомцев одновременно.
- Синхронизация между устройствами, аккаунты, облачный backend и магазин Pet Pack.
- Встроенный редактор или генератор визуалов.
- Гарантированная поддержка GNOME, wlroots, Windows и macOS.
- Flatpak как основной канал дистрибуции.
- Самостоятельные незапрошенные обращения к LLM.

## 5. Основные пользовательские сценарии

### US-01. Первый запуск

Пользователь запускает приложение, видит встроенного питомца, выбирает положение, язык и разрешённые источники событий. LLM выключена. До сохранения настроек показывается краткое объяснение, какие данные обрабатываются локально.

Критерий: от установки до живого питомца — не более 2 минут без регистрации и сетевого доступа.

### US-02. Повседневное присутствие

Питомец остаётся поверх рабочего стола, анимация плавная, клики внутри его визуальной области обрабатываются, прозрачная часть окна не мешает работе настолько, насколько позволяет выбранная геометрия поверхности.

Критерий: после перезапуска сессии восстанавливаются монитор, край, отступ и масштаб.

### US-03. Реакция на простой и возвращение

После настраиваемого периода простоя питомец становится сонным/засыпает. После возобновления активности — просыпается и не чаще одного раза за cooldown показывает реплику.

### US-04. Питание

При подключении питания — `charging`; при пересечении порога низкого заряда — `low_battery`. Повторные обновления одного состояния не создают новые реплики.

### US-05. Контекст приложения

При смене активного приложения опциональная интеграция KWin отправляет только app id. Rule engine может выбрать `busy` или `curious`, но не обращается к LLM без отдельного разрешения.

### US-06. Локальные и LLM-реплики

При выключенной или недоступной LLM всегда используется локальный шаблон. При включённой LLM отправляется минимальный семантический контекст, например `{emotion: "charging", locale: "ru"}`, а не исходное D-Bus-событие.

### US-07. Импорт питомца

Пользователь выбирает Pet Pack. До установки валидатор проверяет manifest, форматы, лимиты размеров и отсутствие исполняемого содержимого. Некорректный пакет отклоняется с понятным списком ошибок.

## 6. Функциональные требования

### FR-1. Overlay и размещение

- Поверхность создаётся через LayerShellQt.
- Поддерживаются углы и края экрана, отступы, масштаб 75–200% и выбор монитора.
- При отключении монитора питомец переносится на основной экран.
- Поведение на полноэкранных приложениях настраивается: скрывать или оставлять видимым.
- Рабочая область окна максимально близка к видимым границам текущего кадра питомца.

### FR-2. Интерактивность

- Левый клик вызывает дружелюбную реакцию с cooldown.
- Drag изменяет якорь/отступ, но не запускает реплику на каждом движении.
- Правый клик открывает меню.
- Должна быть доступна команда «пауза», прекращающая реакции, но сохраняющая tray.

### FR-3. Системные адаптеры KDE Wayland

- Idle/active: KIdleTime.
- Батарея и питание: UPower по D-Bus.
- Сон/возобновление и состояние сессии: `org.freedesktop.login1` и доступные сигналы Plasma/session.
- Активное приложение: отдельный, явно устанавливаемый KWin script/plugin с минимальным payload.
- Медиа: MPRIS по session D-Bus.
- Уведомления: capability-gated Plasma integration; при отсутствии надёжного источника функция отключена, без перехвата содержимого.

### FR-4. Нормализованная модель событий

```rust
enum DesktopEvent {
    ActivityResumed,
    IdleThresholdReached { seconds: u32 },
    PowerChanged { on_battery: bool, percent: Option<u8>, state: PowerState },
    SessionChanged { state: SessionState },
    ActiveAppChanged { app_id: Option<String> },
    NotificationOccurred { category: Option<String> },
    MediaChanged { state: MediaState },
    PetClicked,
}
```

Каждый адаптер публикует capability и состояние здоровья: `available`, `permission_required`, `unsupported`, `degraded`.

### FR-5. Поведение

Rule engine принимает событие и текущее состояние, затем возвращает `Reaction`:

```rust
struct Reaction {
    emotion: Emotion,
    animation: AnimationId,
    phrase_intent: Option<PhraseIntent>,
    priority: u8,
    ttl_ms: u32,
    cooldown_key: Option<String>,
}
```

Правила детерминированы и тестируются без UI. Более приоритетное состояние временно прерывает менее приоритетное. Начальный порядок: `low_battery` → `notification` → `charging` → `happy/curious` → `busy` → `sleepy` → `idle`.

### FR-6. Реплики

- Шаблоны выбираются по `phrase_intent`, эмоции и locale.
- Повторы одной фразы не допускаются в настраиваемом окне истории.
- Пузырь закрывается автоматически и по клику.
- LLM ограничена коротким ответом, тайм-аутом и запретом Markdown/инструкций.
- Ошибка, rate limit или offline прозрачно переключают ответ на локальный шаблон.

### FR-7. LLM Gateway

Единый контракт:

```rust
trait PhraseProvider {
    async fn health_check(&self) -> ProviderStatus;
    async fn generate(&self, request: PhraseRequest) -> Result<Phrase, ProviderError>;
}
```

MVP-адаптеры:

- Ollama: локальный URL и выбранная модель.
- OpenAI-compatible: base URL, model, API key и дополнительные безопасные headers.
- Google Vertex AI: project, region, model и поддерживаемый механизм Application Default Credentials/OAuth.

Секреты не записываются в обычный конфиг; на KDE используются KWallet/Secret Service. В диагностике они всегда редактируются.

### FR-8. Pet Pack v1

Пакет — спрайтовый лист с сеткой ([ADR-005](adr/0005-pet-pack-sprite-sheet.md)).
Общая сетка гарантирует согласованность canvas и точки привязки между
состояниями по построению, а не аккуратностью автора.

```text
pet-pack/
├── manifest.json
├── preview.png
├── sheet.png
└── phrases/
    ├── ru.json
    └── en.json
```

Минимальный manifest:

```json
{
  "schemaVersion": 1,
  "renderer": "sprite-sheet",
  "id": "org.example.pet",
  "name": "Example Pet",
  "version": "1.0.0",
  "sheet": "sheet.png",
  "grid": { "columns": 8, "rows": 11, "cellWidth": 192, "cellHeight": 208 },
  "animations": {
    "idle":  { "row": 0, "startColumn": 0, "frames": 6, "frameDurationMs": 220 },
    "happy": { "row": 3, "startColumn": 0, "frames": 4, "frameDurationMs": 150 }
  },
  "fallbackAnimation": "idle",
  "locales": ["ru", "en"]
}
```

Поле `renderer` обязательно, хотя допустимое значение пока одно. Оно
существует ради второго формата: спрайты принципиально не дают плавной
анимации, и векторный или скелетный формат появится после MVP (§15).
Без явного дискриминатора его добавление превратится в угадывание
по расширению файла.

Ограничения v1:

- Только JSON и PNG. Лист — один файл.
- Размер листа не превышает 8192×8192: пакет, собранный на хорошем GPU,
  должен открываться и на слабом.
- Никаких скриптов, бинарных плагинов, HTML/SVG с активным содержимым
  и внешних URL.
- Архив распаковывается с защитой от path traversal и zip bombs.
- Текстура не больше 16 МиБ в RGBA, объявленные кадры покрывают не меньше
  40% ячеек сетки: текстура занимает память целиком, сколько бы кадров
  ни было объявлено.
- Проверки применяются к файлу целиком, а не только к объявленным кадрам:
  иначе через неиспользуемую область листа можно пронести непроверенное
  содержимое.
- Лимиты на общий размер, число кадров и длительность анимации задаются
  валидатором.
- Длительность кадра — одна на анимацию. Покадровая может появиться в v2
  как необязательное поле.
- Несколько состояний могут использовать одну строку листа с разным
  `startColumn`.
- Отсутствующие состояния используют `fallbackAnimation`.
- Неизвестный `renderer` или `schemaVersion` отвергается с внятным
  сообщением, а не разбирается по догадке.

Понятия спрайтового листа не пересекают границу ядра и ViewModel: ядро
называет анимацию именем состояния, строки и кадры остаются внутри слоя
отрисовки.

## 7. Нефункциональные требования

| Категория | Цель MVP |
|---|---|
| Запуск | Питомец виден не позднее 3 секунд после старта на эталонном устройстве |
| Память | `Private_Dirty` до 60 МБ с одним питомцем; PSS и RSS фиксируются справочно вместе с составом графического стека |
| CPU | В среднем до 2% одного ядра в idle; анимация не вызывает busy loop |
| Плавность | 60 FPS при возможности, без блокировки event loop; graceful fallback до 30 FPS |
| Сеть | Ноль запросов, пока пользователь явно не включил LLM |
| Надёжность | Сбой адаптера/LLM не завершает overlay; последний валидный Pet Pack остаётся рабочим |
| Приватность | Сырые события не сохраняются; журнал по умолчанию кольцевой и обезличенный |
| Доступность | Настройка масштаба, отключение реплик и анимаций, reduced motion |
| Локализация | UI и встроенные фразы: ru/en; fallback всегда определён |
| Совместимость | Plasma 6.2+, Qt 6; точная матрица дистрибутивов фиксируется после spike |

## 8. Архитектура

```text
QML UI
  ↓ UI intents / ViewModel
Qt/KDE Desktop Host (C++)
  ├─ LayerShellQt, tray, KIdleTime, D-Bus
  ├─ KDE Wayland adapters
  └─ thin Rust bridge
          ↓ normalized events
Rust Core
  ├─ behavior/state machine
  ├─ phrase/template engine
  ├─ LLM gateway
  ├─ Pet Pack validation
  └─ config domain model
```

Граница между host и core должна передавать только стабильные DTO, а не Qt-типы. Для MVP выбирается один FFI-подход после технического spike; предпочтение — статическая Rust-библиотека с узким C ABI и безопасной C++-обёрткой. Это снижает связанность с конкретным binding framework.

Предлагаемая структура репозитория:

```text
apps/desktop-kde/          # entry point, packaging
ui/qml/                    # общий QML UI
core/                      # Rust domain core
platform/contracts/        # capability и DTO-контракты
platform/kde-wayland/      # Qt/KF6/LayerShellQt adapters
pet-pack/schema/           # JSON Schema
pet-pack/validator/        # безопасная проверка пакетов
assets/builtin-pet/        # встроенный эталонный пакет
tests/fixtures/            # события и Pet Pack fixtures
docs/                      # ADR и privacy model
```

## 9. Хранение данных и приватность

Локально сохраняются:

- настройки UI и разрешённых capabilities;
- выбранный Pet Pack и его проверенный hash;
- параметры LLM без секретов;
- короткая история идентификаторов показанных фраз для защиты от повторов;
- обезличенная диагностика уровня warning/error.

Не сохраняются:

- клавиши, текст ввода, координаты мыши;
- заголовки документов и содержимое окон;
- текст и отправители уведомлений;
- аудио, скриншоты и clipboard;
- полная временная история активных приложений.

Перед первым включением сетевого провайдера UI показывает точный payload-пример. Для каждого класса событий есть отдельный toggle. «Сбросить локальные данные» удаляет настройки и историю, не удаляя вручную импортированные Pet Pack без отдельного подтверждения.

## 10. Ошибки и деградация

| Ситуация | Поведение |
|---|---|
| Нет LayerShellQt | Понятная ошибка совместимости; диагностический запуск обычного окна допускается только dev-флагом |
| KIdleTime недоступен | Реакции idle отключены, остальные работают |
| KWin integration не установлена | Активное приложение = `unsupported`; установка предлагается отдельно |
| UPower отсутствует | Скрываются правила питания |
| LLM недоступна | Немедленный fallback на локальный шаблон после короткого timeout |
| Pet Pack повреждён | Откат на последний валидный или встроенный пакет |
| Монитор исчез | Перенос на primary screen с безопасным отступом |
| Частый поток событий | Debounce, coalescing и cooldown до попадания в UI |

## 11. Тестовая стратегия

- Unit: state machine, приоритеты, cooldown, шаблоны, redaction, Pet Pack validator.
- Contract: каждый platform adapter проходит общий набор тестов capabilities и DTO.
- Integration: fake D-Bus services для UPower/MPRIS/login1 и записанные безопасные event fixtures.
- UI: QML component tests для состояний, scale и reduced motion.
- E2E на реальной Plasma Wayland: позиционирование, restart session, multi-monitor, suspend/resume, battery transitions.
- Security: path traversal, decompression bomb limits, malformed media, secret redaction.
- Manual UX soak: 4–8 часов фоновой работы для оценки частоты и раздражающего поведения.

## 12. Roadmap MVP

Оценка дана для одного разработчика на полной занятости и включает резерв на незнакомые KDE/Wayland API. Это ориентир, не календарное обещание.

| Этап | Оценка | Результат | Критерий выхода |
|---|---:|---|---|
| M0. Technical spikes | 1 неделя | Мини-пробы LayerShellQt, QML animation, KIdleTime, Rust↔C++ bridge | Overlay работает в Plasma Wayland; главный FFI-риск снят |
| M1. Walking skeleton | 1 неделя | Репозиторий, CI, desktop host, tray, встроенный питомец, mock events | Приложение устанавливается и показывает кликабельного питомца |
| M2. Behavior core | 1 неделя | Rust state machine, reaction priorities, cooldown, template phrases | Детерминированные сценарии покрыты unit tests |
| M3. KDE base integration | 1–1.5 недели | Idle, UPower, sleep/resume, session lock, capability health | События воспроизводимо меняют состояние на реальной Plasma |
| M4. Context integrations | 1–1.5 недели | KWin active-app module, MPRIS, notification feasibility/fallback | Ни один адаптер не читает запрещённое содержимое; graceful degradation работает |
| M5. Pet Pack v1 | 1 неделя | Schema, validator, импорт, fallback assets, локализации | Невалидные/опасные пакеты отклоняются; валидный пакет меняется без переустановки |
| M6. LLM gateway | 1–1.5 недели | Ollama, OpenAI-compatible, Vertex AI, secrets, health check, fallback | Каждый провайдер проходит contract test; offline режим не ломается |
| M7. Hardening и alpha | 1.5–2 недели | Настройки, автозапуск, diagnostics, perf, accessibility, packaging | Выполнен Definition of Done и 8-часовой soak test |

Итого: примерно **9–11.5 недель** до закрытой alpha одним разработчиком. Без Vertex AI и глубокой интеграции уведомлений первая полезная alpha возможна примерно за **6–8 недель**.

## 13. Definition of Done MVP

MVP считается завершённым, когда:

1. На поддерживаемой Plasma Wayland-системе питомец устанавливается, запускается и восстанавливает позицию.
2. Все восемь состояний имеют анимацию или корректный fallback.
3. Idle, питание и sleep/resume работают стабильно; остальные интеграции явно сообщают capability.
4. Никакие клавиши, тексты, экран или аудиопотоки не собираются.
5. Без сети доступны все основные реакции и локальные реплики.
6. Ollama, OpenAI-compatible и Vertex можно настроить, проверить и выключить; ошибка всегда ведёт к локальному fallback.
7. Валидный Pet Pack импортируется, опасный/повреждённый — безопасно отклоняется.
8. CPU/RAM соответствуют целям на зафиксированном эталонном устройстве либо отклонение документировано.
9. Есть автоматические unit/contract tests и пройден ручной 8-часовой soak.
10. Пользователь может отключить любой источник событий, приостановить реакции и удалить локальные данные.

## 14. Риски и решения

| Риск | Вероятность / влияние | Митигация |
|---|---|---|
| Разное поведение layer-shell между версиями Plasma | Средняя / высокая | M0 spike, фиксированная compatibility matrix, изоляция adapter |
| Интерактивная прямоугольная поверхность перекрывает клики прозрачными областями | Высокая / высокая | Динамическая input region или компактная геометрия; проверить в M0 |
| Активное приложение недоступно обычному Wayland-клиенту | Высокая / средняя | Отдельный согласованный KWin module, capability toggle |
| Нельзя надёжно наблюдать все чужие уведомления | Высокая / средняя | Не обещать контент; optional Plasma module или `unsupported` |
| FFI Qt/Rust замедляет разработку | Средняя / высокая | Узкий DTO API, один spike, возможность временно держать orchestration в C++ |
| Vertex auth усложняет onboarding | Средняя / средняя | ADC/OAuth, отдельный setup guide, не блокировать offline MVP |
| Анимации потребляют CPU/GPU | Средняя / средняя | Frame caps, pause when hidden/locked, performance budget |
| Питомец быстро начинает раздражать | Средняя / высокая | Cooldown, quiet hours, pause, frequency presets, soak testing |

## 15. Решения после MVP

### P1 — расширение продукта

- Windows adapter.
- macOS adapter.
- GNOME/wlroots feasibility и отдельные hosts при необходимости.
- Несколько питомцев, сценарии взаимодействия и расширенные эмоции.
- Rive как дополнительный профессиональный формат.
- Подписанные Pet Pack и каталог пакетов.
- Более точные quiet hours и контекстные профили.

### Отдельный workstream — skill генерации питомцев

Универсальный skill для разных агентов реализует процесс:

1. описание/референс;
2. согласование концепта и палитры;
3. генерация обязательных состояний;
4. нормализация canvas, прозрачности и anchor;
5. проверка межкадровых скачков и лимитов;
6. формирование preview, manifest и фраз;
7. запуск официального Pet Pack validator;
8. выдача переносимого пакета без исполняемого кода.

Skill не является частью runtime-приложения и не блокирует MVP. Контракт Pet Pack v1 должен стабилизироваться до реализации skill.
