# Задание на перерисовку встроенного питомца

Документ для того, кто рисует спрайтовый лист. Код к перерисовке готов:
процедурное движение реализовано ([ADR-009](../../docs/adr/0009-procedural-motion-layer.md)),
и траекторию больше не нужно рисовать кадрами.

## Что не так сейчас

Измерено на текущем листе, а не замечено на глаз.

**Прыжок уменьшает питомца.** В строке `jumping`, на которой сделано
состояние `charging`, фигура нарисована мельче остальных, чтобы траектория
прыжка поместилась в ячейку 192×208. Разброс высоты фигуры внутри строки —
**24.5%**. На экране это читается как изменение размера питомца, а не как
высота прыжка.

**Фигура смещается по горизонтали.** Центр масс гуляет на 2–9 px внутри
одной анимации, отчего питомец слегка плавает влево-вправо. Заметнее всего
в состояниях, которые должны быть спокойными.

## Что изменилось в коде

Траекторию теперь задаёт манифест, а не кадры. Прыжок описывается так:

```json
"charging": {
  "row": 2, "startColumn": 0, "frames": 5, "frameDurationMs": 120,
  "motion": {
    "durationMs": 900,
    "loop": true,
    "keyframes": [
      { "at": 0.0, "x": 0, "y": 0,   "easing": "out-quad" },
      { "at": 0.5, "x": 0, "y": -40, "easing": "in-quad"  },
      { "at": 1.0, "x": 0, "y": 0 }
    ]
  }
}
```

Приложение само поднимает питомца на 40 логических пикселей и опускает
обратно, с плавностью и привязкой к физическим пикселям экрана.

**Значит, кадры прыжка должны показывать только позу:** группировку перед
толчком, вытянутое тело в воздухе, приземление. Высоту рисовать не надо
и не нужно уменьшать фигуру ради неё.

## Требования к новому листу

### Обязательные

| Правило | Значение | Сейчас |
|---|---|---|
| Размерность | ≤ 8192×8192 | 1536×1456 |
| Текстура RGBA | ≤ 16 МиБ | 8.5 МиБ |
| Объявленные кадры | ≥ 40% ячеек сетки | 77% |
| Формат | PNG, один файл | PNG |

Нарушение любого — отказ при импорте.

### Проверяемые автоматически

**Размер фигуры внутри строки должен быть постоянным** там, где поза
не меняется по-настоящему. Проверка при импорте ловит дрожание по признаку
«фигура скачет между кадрами»: считается отношение суммы покадровых
изменений высоты к общему размаху. У плавного движения оно 1.0–2.6,
у дрожания — выше 3.5.

Сейчас у всех восьми состояний отношение в норме, и эту норму надо
сохранить.

### Желательные, но не проверяемые

**Горизонтальный центр масс.** Сейчас гуляет на 2–9 px. Проверка это
не ловит — она смотрит только высоту. Чем стабильнее центр, тем меньше
питомец «плавает».

**Одинаковая точка опоры.** Низ фигуры в сидячих позах должен стоять
на одном уровне: сейчас разброс доходит до 19 px, и это заметно.

## Раскладка

Восемь состояний §4.1 обязаны быть отрисованы или сведены к `fallbackAnimation`.
Текущая раскладка — в [`README.md`](README.md) рядом. Строки можно
переставлять и объединять: сопоставление задаёт манифест, а не порядок.

Два состояния могут делить одну строку с разным `startColumn` — так сейчас
сделаны `sleepy` и `low_battery`.

Неиспользуемые строки дороги: текстура занимает память целиком. У прежнего
листа четыре пустые строки из одиннадцати стоили 8 МиБ, их вырезали.

## Как проверить свой лист

Собрать zip с `manifest.json` и листом, затем:

```bash
OPENPET_IMPORT_PACK=/путь/к/pack.zip QT_FORCE_STDERR_LOGGING=1 \
  QT_LOGGING_RULES='openpet.*=true' ./build/apps/desktop-kde/open-pet
```

Выведет вердикт и все замечания: отказ с причинами либо «установлен»
со списком предупреждений.

## О чём стоит знать про движение

**Зацикленное движение в состоянии покоя работает всегда.** Замерено:
непрерывное движение стоит 6.8% ядра против 0.3% у неподвижного питомца.
Валидатор об этом предупредит. Для `idle` лучше обойтись без `motion`
или сделать его коротким и незацикленным.

**Резерв поверхности берётся по крайним точкам всех траекторий пакета.**
Прыжок на 40 px вверх означает, что окно постоянно на 40 px выше. Большие
траектории оплачиваются памятью и композитингом всё время, а не только
во время движения.

**Смещения ограничены 256 логическими пикселями** в любую сторону.
