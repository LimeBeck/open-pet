# Спайк 01 — layer-shell overlay и input region

Отвечает на вопросы [ADR-002](../../docs/adr/0002-overlay-input-region.md) и заодно
снимает часть риска M0 «overlay работает в Plasma Wayland».

## Что проверяется

1. Создаётся ли настоящая layer-shell поверхность, а не обычное окно.
2. Доходит ли `QWindow::setMask()` до Wayland как `set_input_region`.
3. Во что обходятся четыре стратегии региона из ADR-002.
4. Меняется ли силуэт между кадрами настолько, чтобы вариант C вообще имел смысл.

Питомец нарисован примитивами QML специально с дырами в силуэте: клин между
ушами, промежуток между лапами, поля вокруг и полупрозрачная тень. Именно эти
места отвечают на вопрос «проваливается ли клик к окну снизу».

## Сборка и запуск

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo && cmake --build build
```

```bash
QT_FORCE_STDERR_LOGGING=1 OPENPET_REGION=2 ./build/openpet-spike-overlay
```

`QT_FORCE_STDERR_LOGGING=1` обязателен: на Plasma логи Qt по умолчанию уходят
в journald, и stdout остаётся пустым.

| Переменная | Значение |
|---|---|
| `OPENPET_REGION` | `0` без региона, `1` вариант A, `2` вариант B, `3` вариант C |
| `OPENPET_HUD` | `0` скрывает панель с цифрами (её площадь входит в регион) |
| `OPENPET_ANCHOR` | `bottom-right` (по умолчанию), `bottom-left`, `top-right`, `top-left` |
| `OPENPET_MARGIN_RIGHT`, `OPENPET_MARGIN_BOTTOM` | отступы в пикселях |

ПКМ по питомцу переключает стратегию на лету, ЛКМ — засчитывает клик.
Клавиатура окну недоступна намеренно: `KeyboardInteractivityNone`.

## Результаты

Замерено на эталонной системе из [`docs/reference-system.md`](../../docs/reference-system.md):
Intel Iris Xe, дисплей 2880×1800@90 Гц, масштаб 1.75, Plasma 6.7.4, Qt 6.11.1.
Окно 300×260 логических пикселей, HUD выключен, по 20 секунд на режим,
первые 5 секунд отброшены.

| Стратегия | FPS | CPU | RSS | Прямоугольников | Пересчётов/с | Стоимость |
|---|---:|---:|---:|---:|---:|---:|
| Без региона | 90 | 4–6% | 282 МиБ | — | 0 | — |
| A: статический прямоугольник | 90 | 4–6% | 283 МиБ | 1 | 0 | однократно |
| B: альфа однократно | 90 | 4–6% | 291 МиБ | 49 | 0 | 33 мс на старте |
| C: альфа покадрово | 90 | **19–22%** | 294 МиБ | 46–50 | ~90 | 10.8 мс на пересчёт |

Время до первого кадра, 5 запусков: 213, 231, 253, 258, 258 мс.

### Что подтвердилось

**Поверхность настоящая.** В трафике Wayland видно `zwlr_layer_shell_v1`
и ровно один `get_layer_surface`; `xdg_toplevel` не создаётся вовсе. Поверхность
принимает `set_anchor`, `set_margin`, `set_exclusive_zone`,
`set_keyboard_interactivity`. Это закрывает вопрос «overlay не ощущается обычным
окном» на уровне протокола.

**`setMask()` работает как надо.** Проверено по трафику, а не на глаз:

| Режим | `set_input_region` | Прямоугольников в `wl_region` |
|---|---:|---:|
| 0 (без региона) | 0 | 0 |
| 1 (вариант A) | 1 | 1 |
| 2 (вариант B) | 1 | 49 |

**`grabWindow()` на layer-shell поверхности не пустой.** Это было главным
техническим сомнением: без него варианты B и C отпадали бы целиком.

**Дробный масштаб не ломает координаты.** На scale 1.75 регион приходит
в поверхностных координатах и укладывается в границы окна 300×260 — пересчёт
через `devicePixelRatio` с округлением наружу отрабатывает верно.

**Силуэт действительно меняется.** В варианте C число прямоугольников гуляет
46→50 в такт дыханию, то есть покадровый пересчёт не был бы холостым.

### Что не подтвердилось

**Вариант C не проходит по бюджету.** 19–22% ядра против цели §7 «в среднем
до 2% в idle» — это в десять раз мимо. Причём FPS не просел: цена ушла в CPU,
а не в плавность, и на ноутбуке это прямо конвертируется в расход батареи.
Отдельно неприятно, что стоимость привязана к частоте кадров: на дисплее 90 Гц
пересчёт идёт 90 раз в секунду.

### Что настораживает, но к ADR-002 не относится

- **RSS 282–294 МиБ против цели §7 в 150 МиБ.** Это пустое окно на примитивах
  QML, без единого WebP. Цель §7 выглядит недостижимой для стека Qt Quick
  в текущем виде — вопрос требует отдельного разбора и, возможно, правки §7.
- **CPU 4–6% в покое против цели 2%.** Анимация QML идёт без ограничения
  частоты: питомец перерисовывается 90 раз в секунду на дисплее 90 Гц.
  Frame cap из §14 («анимации потребляют CPU/GPU») нужен не как оптимизация,
  а как условие попадания в бюджет.
- Оба числа сняты со сборки `RelWithDebInfo` с включённым QML-кэшем,
  но без `QML_DISABLE_DISK_CACHE` и без оптимизации размера.

### Проверено руками

Клик по прозрачному пикселю рядом с питомцем уходит в окно снизу, клик
по видимому — обрабатывается приложением. Мёртвой зоны вокруг питомца нет.

Воспроизведение:

```bash
QT_FORCE_STDERR_LOGGING=1 OPENPET_REGION=2 ./build/openpet-spike-overlay
```

Открыть под питомцем любое окно и щёлкнуть: в клин между ушами, в промежуток
между лапами, по тени и по самому питомцу. Первые три уходят в окно снизу,
последний попадает в лог как «клик N».

Закрывается только снаружи — у окна нет ни рамки, ни клавиатуры, ни трея:

```bash
pkill -x openpet-spike-overlay
```
